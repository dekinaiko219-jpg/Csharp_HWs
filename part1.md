задание 1.1
1. Использование List<IDamageable> позволяет работать с разными объектами, которые реализуют один интерфейс. Например, в один список можно добавить как Player, так и Trap. Несмотря на то что это разные классы, у них есть общий метод TakeDamage(), который каждый класс реализует по-своему. Благодаря полиморфизму GameSystem может обрабатывать все эти объекты через один метод, не создавая отдельную реализацию для каждого класса. Это делает код более универсальным и удобным для расширения.
2. Формально класс Trap не нарушает контракт интерфейса, поскольку реализует все его методы и свойства. Однако его поведение отличается от того, что можно ожидать от обычного объекта, получающего урон. Вместо уменьшения HP ловушка сразу разбивается и возвращает false. Для вызывающего кода это может быть неожиданно, поскольку он не знает внутренних особенностей реализации Trap. Поэтому такое поведение стоит явно учитывать при проектировании интерфейса.
3. HealthPotion реализует интерфейс IHealable, поэтому его нельзя передать в метод ProcessDamage(), который принимает List
4. После добавления свойства IsDead придётся изменить оба класса: Player и Trap, поскольку они реализуют интерфейс IDamageable. В каждом классе необходимо добавить реализацию нового свойства. Например, для Player оно будет возвращать true, если HP меньше или равно нулю, а для Trap можно возвращать true после её разрушения. Если не добавить это свойство, программа не скомпилируется, поскольку классы не будут полностью реализовывать контракт интерфейса.
